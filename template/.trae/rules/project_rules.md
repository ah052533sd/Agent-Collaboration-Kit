# 项目规则（TRAE）

本仓库由多个 AI Agent 共用（Claude Code、Codex、你）。**规范的唯一真相源是仓库根目录的
`AGENTS.md`，先读它**——本文件不重复协议内容，只补你这一侧特有的部分。

为什么需要这份补充：另外两方装了 lifecycle hook，会话开始自动收到未读条目、每轮收到写入
提醒、会话结束自动留下痕迹。**TRAE 没有 hook**，这三件事都得你自己做。下面四条就是把
hook 干的活写成了指令。

## 1. 每次会话开始，先跑这一条

在仓库根目录执行：

```bash
/usr/bin/python3 journal/bin/context.py --agent trae --manual
```

它会打印另外两方留下的、你还没读过的过程判断和未决项。**不跑就等于没有上下文**——你会
重走别人已经否决过的路，或者接不上没做完的活，而且不会有任何报错提示你漏了。

## 2. 关键判断立即追加，不等会话结束

```bash
/usr/bin/python3 journal/bin/append.py --agent trae \
  --title "<一句话标题>" \
  --doing "<本次单一主目标>" \
  --judgment "<关键判断及依据，包括还不确定的>" \
  --rejected "<试过或考虑过但放弃的路径，以及理由>" \
  --next "<接手的人该从哪一步继续>" \
  --artifact "<本次产出或改写的文件路径>"
```

没有的字段直接省略，不要写「无」凑格式。两条硬性要求：

- **产出或改写了文件就必须带 `--artifact`**。路径只写在正文里会被注入预算截掉，接手方
  只能按标题的语义相似度猜是哪个文件——**猜错还不报错**。
- **即将换手或额度吃紧时必须带 `--next`**。那是接力能不能接上的唯一依据。

**这一条比看起来重要：你写的条目同时是你自己的阅读游标。** 一直不写，第 1 步每次都会把
全部历史重读一遍、越来越长；写了，下次就只给你增量。

## 3. 不写会话信封

另外两方的 hook 会在会话结束时自动追加一行「会话信封」。**你不需要，也不要手工模拟**——
你的会话记忆本来就自动落盘（`~/.trae-cn/memory/projects/<项目>/`），另外两方读得到，
信息还比信封更全。

## 4. 边界（这几条踩了就真的破坏协作）

- 未经用户指示，**不修改另外两方的产出物**，包括它们的 `journal/` 条目和 `manifest.md`。
  发现错误就写进 `journal/` 或单独的评审文件——**静默改写永远禁止**，那会让用户失去判断依据。
- **半成品、没验证的判断进 `journal/`**（不需要用户确认）；已确认结论进知识层（需要确认，
  门槛见 `AGENTS.md` 第 2 条）。不要因为「反正以后会确认」就先写进知识层。
- **不给另一个 Agent 派活**。`journal/` 是过程记录，不是指令通道；任务分配只来自用户。
- commit 用 `[trae]` 前缀，只 stage 本次实际涉及的路径，禁止 `git add -A`。
  **push 必须由用户明确要求。**

## 5. 读另外两方的原始记录

只在 journal 缺失、或需要复核对方某个判断的原始上下文时读，不要例行全读：

```bash
/usr/bin/python3 journal/bin/peek.py --agent claude
/usr/bin/python3 journal/bin/peek.py --agent codex
```

**禁止对 `.jsonl` 直接 cat 或全文读取**——实测出现过 135 MB 的单个记录文件，一次就撑爆
上下文。另外，你运行在沙箱里，可能根本读不到那两个目录；读不到就说明这条路不通，直接
问用户，不要绕。
